# plan/ 结构（扁平模块文件）

阶段 2 在 `plan/` 下写**技术方案 + 分模块验收**。产品目标以 `需求.md`（PRD）为准，**技术栈只出现在 plan**，不在 HTML 选题里问用户。

## 目录约定

```
plan/
  技术方案.md              ← 阶段 2 首写：技术栈、目录结构、部署、数据流（依据 PRD）
  当前步骤.md              ← Agent 辅导指针（唯一动态文件）
  M01-<模块名>.md          ← 实现与验收（可引用技术方案.md）
  M02-<模块名>.md
  …
```

- **禁止** `plan/Mxx/验收.md` 子目录。
- **不要** `plan/README.md`（模块索引写在 `当前步骤.md`）。
- 模块文件名：`M{两位序号}-{中文模块名}.md`。

## plan/技术方案.md 必含章节

1. **技术选型结论**（如：单页 HTML+JS / Vite、是否 PWA、是否静态托管）及**选用理由**（对应 PRD 哪条）。
2. **项目结构**（文件/目录清单）。
3. **运行与部署**（本地 HTTP、是否上 Pages 等）。
4. **数据流**（词库加载、状态放内存还是 localStorage 等）。
5. **与 PRD 的对应表**（PRD 决策 → 实现要点）。

Agent 写 plan 时：**先**产出 `技术方案.md`，**再**写 `M01-….md` …；`M01` 起头应写「技术依据：见 `技术方案.md`」。

## plan/当前步骤.md 示例

```markdown
# 当前步骤

- **阶段**：技术方案已定，进入模块实现
- **模块**：M01 项目骨架与词库
- **模块文件**：`plan/M01-项目骨架与词库.md`
- **步骤**：操作步骤 · 第 1 步
- **你要做**：…
```

首次进入阶段 2 时，可先将 `当前步骤.md` 指向「阅读并确认 `技术方案.md`」，再进入 M01。

## Agent 行为

1. 用户说「写 plan」→ 读已定 `需求.md` → 写 `plan/技术方案.md` → 再写各 `Mxx-….md` → 初始化 `当前步骤.md`。
2. 辅导时只推 `当前步骤.md` 中的一步；通过后再更新指针。
3. **禁止**在 plan 里推翻 PRD 已定的产品决策；若 PRD 与实现冲突，先改 PRD 或技术方案并说明。
